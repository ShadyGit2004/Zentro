API Design v1.0 — Twitter/X Clone
1. API Overview

Style: REST API
Data format: JSON
Base path:

/api/v1

Example:

GET /api/v1/users/me
POST /api/v1/posts
Authentication

Protected requests:

Authorization: Bearer <firebase-id-token>

Firebase ID token = Firebase login ke baad milne wala token. Backend Firebase Admin SDK se verify karega.

2. Common API Rules
Headers

JSON request ke liye:

Content-Type: application/json

Authenticated request:

Authorization: Bearer <firebase-id-token>
3. Standard Success Response

Single resource:

{
  "success": true,
  "data": {}
}

Collection:

{
  "success": true,
  "data": [],
  "pagination": {}
}
4. Standard Error Response

Har API error ko predictable rakhenge:

{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "details": {}
  }
}

details optional hai.

Example:

{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "details": {
      "content": "Content is required"
    }
  }
}
5. HTTP Status Codes
Status	Meaning
200	Successful request
201	Resource created
204	Successful deletion/no body
400	Bad request
401	Not authenticated
403	Not authorized
404	Resource not found
409	Conflict
422	Validation failed
429	Rate limit exceeded
500	Internal server error
6. Pagination Standard

Initial implementation:

?page=1&limit=20

Rules:

page >= 1
limit >= 1
limit <= 100

Example:

GET /api/v1/feed?page=1&limit=20

Response:

{
  "success": true,
  "data": [],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 125,
    "totalPages": 7,
    "hasNextPage": true,
    "hasPreviousPage": false
  }
}
Why limit max 100?

Client ko accidentally:

?limit=1000000

bhej kar database par huge query nahi karne deni.

Later large-scale feed ke liye cursor-based pagination consider karenge.

14. Business Rules

Ye API design ka bahut important part hai.

BR-01: User must be authenticated for protected APIs.

BR-02: Firebase ID token must be verified server-side.

BR-03: Firebase UID maps to MongoDB User.

BR-04: User cannot follow themselves.

BR-05: Duplicate follows are forbidden.

BR-06: Duplicate likes are forbidden.

BR-07: User can edit only their own posts.

BR-08: User can delete only their own posts.

BR-09: Post must belong to an existing user.

BR-10: Comment must belong to an existing post and user.

BR-11: Like must belong to an existing post and user.

BR-12: Follow must reference existing users.

BR-13: Backend validates every client input.

BR-14: Frontend validation does not replace backend validation.

BR-15: Passwords are never stored in MongoDB.

BR-16: Pagination limits must be enforced server-side.

   ↓

   ↓

   ↓

Important terminology

Rate Limiting → ek user/IP kitni requests limited time mein kar sakta hai.

CORS → kaunse frontend origins API ko access kar sakte hain.

Helmet → Express responses mein common security-related HTTP headers configure karta hai.

Authentication → user kaun hai?

Authorization → user ko ye action karne ki permission hai ya nahi?

Validation → input expected format mein hai ya nahi?

Ownership Check → resource actually current user ka hai ya nahi?

1. Authentication APIs
Register
POST /api/v1/auth/register

Body:

{
  "email": "user@example.com",
  "username": "rajat",
  "displayName": "Rajat",
  "password": "********"
}

Response:

{
  "success": true,
  "data": {
    "user": {},
    "accessToken": "..."
  }
}

Refresh token → HttpOnly Secure cookie.

Login
POST /api/v1/auth/login

Body:

{
  "email": "user@example.com",
  "password": "********"
}

Returns application accessToken and sets refresh-token cookie.

Google Login
POST /api/v1/auth/google

Body:

{
  "idToken": "<firebase-id-token>"
}

Flow:

Firebase ID Token
      ↓
Backend verifies
      ↓
Find/Create User
      ↓
Create Session
      ↓
Our Access + Refresh Token
Refresh
POST /api/v1/auth/refresh

Refresh token cookie automatically sent.

Backend:

Validate session
      ↓
Rotate refresh token
      ↓
Create new access token
      ↓
Set new refresh cookie
Logout
POST /api/v1/auth/logout

Backend revokes current session and clears refresh cookie.

Verify Email
POST /api/v1/auth/verify-email

Body:

{
  "token": "verification-token"
}
Resend Verification
POST /api/v1/auth/resend-verification

Authenticated user.

Rate limited.

Forgot Password
POST /api/v1/auth/forgot-password

Body:

{
  "email": "user@example.com"
}

Important: Response should not reveal whether that email exists.

Reset Password
POST /api/v1/auth/reset-password

Body:

{
  "token": "reset-token",
  "newPassword": "********"
}

After successful reset, existing sessions should be revoked as a security measure.

Change Password
PATCH /api/v1/auth/password

Protected.

Body:

{
  "currentPassword": "********",
  "newPassword": "********"
}
