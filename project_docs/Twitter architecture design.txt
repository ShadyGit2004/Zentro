🏗️ Twitter/X Clone — Software Architecture Design

Version: 1.0
Project: Twitter/X Inspired Social Media Platform
Architecture Style: Client–Server + REST API
Frontend: Next.js + TypeScript
Backend: Node.js + Express + TypeScript
Database: MongoDB
Authentication: Firebase Authentication
Server State: TanStack Query

1. Architecture ka Purpose

Architecture ka purpose ye define karna hai ki:

System ke different components ek dusre ke saath kaise communicate karenge aur responsibility kis component ki hogi.

SRS mein humne define kiya:

WHAT the system should do

Architecture define karega:

HOW the system will be structured to do it

Example:

Requirement

Architecture batayegi:

    ↓

    ↓

    ↓
Post Controller

    ↓
MongoDB

11. Middleware Layer

Middleware request aur controller ke beech ka security/processing layer hai.

Example:

Request
   ↓
Authentication Middleware
   ↓
Validation Middleware
   ↓
Controller

Authentication middleware:

Firebase ID Token
       ↓
Firebase Admin SDK
       ↓
Token Verify
       ↓
Authenticated User
       ↓
Controller
Authentication vs Authorization

Authentication:

Tum kaun ho?

Authorization:

Tumhe ye kaam karne ki permission hai?

Example:

User A
   ↓
DELETE
   ↓
User B's Post

Authentication successful ho sakti hai.

But authorization fail hogi because:

User A, User B ki post delete nahi kar sakta.

12. Controller Layer

Controller HTTP-related responsibility handle karega.

Example:

POST /api/posts
        ↓
postController.createPost()

Controller:

request read karega
required data service ko dega
response return karega
appropriate HTTP status bhejega

Controller mein heavy business logic nahi rakhenge.

13. Service Layer

Service mein actual business logic hoga.

Example:

postService.createPost()

Service decide karegi:

Is user authenticated?
Is content valid?
Kya user allowed hai?
Post kaise create hogi?
Database ko kya data dena hai?
Why?

Agar business logic controller mein bhar diya:

Controller = 300+ lines

Project difficult maintain hoga.

Layering se:

Controller
    ↓
Service
    ↓
Database

clear responsibility rahegi.

28. Why Separate Frontend and Backend?

Hum Next.js ke andar API routes bana sakte the.

But hum separate Express backend choose kar rahe hain.

Reason

Tumhara learning goal hai:

Backend architecture
REST API
Middleware
Controllers
Services
MongoDB
Authentication
Authorization
API security

Separate Express backend se ye concepts properly practice honge.

Alternative
Next.js
 └── API Routes
      └── MongoDB

Ye valid production architecture ho sakta hai.

But hamare learning objective ke liye separate Express better hai.

31. Architectural Principles

Project mein hum ye principles follow karenge:

1. Separation of Concerns

Har layer ka clear responsibility.

2. Single Responsibility

Ek component ideally ek major responsibility handle kare.

3. Don't Trust the Client

Frontend validation enough nahi hai.

4. Authentication ≠ Authorization

Login hone ka matlab ye nahi ki user sab kuch kar sakta hai.

5. Business Logic in Service Layer

Controllers ko unnecessarily complex nahi banayenge.

6. Server State ≠ UI State

Server data → TanStack Query.

Local UI state → React state/hooks.

7. API First Thinking

Frontend banane se pehle API contract understand/design karenge.

8. Security from Beginning

Security ko end mein add nahi karenge.
